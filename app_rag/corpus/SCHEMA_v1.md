# 참고자료 JSON

팀원이 채우는 파일: `corpus/records.json`

지금 검색 단위는 **레코드 1건**이다. 토큰 길이로 자르지 않는다.
법령이면 조 하나, 해설·사례면 항목 하나가 적당하다. 계약서 입력의 쪼개기와는 별개다.

```json
{
  "records": [
    {
      "id": "근기법:제54조",
      "title": "근로기준법 제54조 휴게",
      "text": "본문 전체",
      "source": "근로기준법",
      "tags": ["휴게", "근로시간"]
    }
  ]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| id | 예 | 리포트에 찍히는 출처 id |
| title | 아니오 | 제목. 검색에도 넣는다 |
| text | 예 | 모델이 읽는 본문 |
| source | 아니오 | 법령명·문서명 |
| tags | 아니오 | 검색 보조 단어 |

다른 키 이름도 받는다: `본문`→text, `법령명`+`조문 번호`→title/source, `id` 그대로.

`records.json`이 비어 있으면 파이프라인이 `exp_v2/law_node_texts.jsonl` 59칸을 대신 쓴다. 팀원 파일이 채워지면 그쪽만 쓴다.
