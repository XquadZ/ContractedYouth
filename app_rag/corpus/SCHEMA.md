# 참고자료 JSON

팀원이 채우는 파일: `corpus/records.json`

검색 단위는 **레코드 1건**이다.

- 법령: 조 1개(항·호 포함). 너무 길면 항마다 나누고 조 제목을 붙인다.
- 판례: 판시사항 + 판결요지
- 표준계약서: 표준 조항 1개
- 고시: 통째

```json
{"id": "law:근로기준법:54", "doc_type": "법률|시행령|고시|판례|표준계약서|해석례",
 "title": "근로기준법 제54조(휴게)", "text": "…원문…", "source": "국가법령정보센터",
 "url": "…", "effective_date": "2026-10-08",
 "domain": ["LAB"], "std_item": ["LAB-04"]}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| id | 예 | 리포트에 찍히는 출처 id |
| doc_type | 예 | 법률 / 시행령 / 고시 / 판례 / 표준계약서 / 해석례 |
| title | 예 | 제목. 검색에도 넣는다 |
| text | 예 | 모델이 읽는 본문 |
| source | 예 | 출처명 |
| url | 예 | 원문 주소. 없으면 빈 문자열 |
| effective_date | 예 | YYYY-MM-DD. 없으면 빈 문자열 |
| domain | 예 | `["LAB"]` / `["LEASE"]` / `["LOAN"]` 배열 |
| std_item | 예 | 확인된 태그만. 사람이 보기 전에는 `[]` |

로더가 필수 필드를 검사한다. 빠지면 그 레코드는 쓰지 않고 목록으로 보고한다.

`std_item` 제안은 `corpus/tag_proposal.csv`에만 둔다. 확인 전에는 레코드의 `std_item`을 비운다.
