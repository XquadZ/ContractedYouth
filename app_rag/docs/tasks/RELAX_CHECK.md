# 문서 판정 기준 완화 실험 (RELAX_CHECK)

`CLAUDE.md` 규칙을 따른다. 판정 프롬프트, 카드, 검색 설정은 바꾸지 않는다. **문서 판정 계산만 바꿔 본다.**
FIX_ROUND2를 이미 시작했다면 그 A단계(조항별 결과 저장) 위에서 하고, 아니면 이 문서를 먼저 한다.

## 1. 조항별 결과를 남기며 다시 돌리기 (근로 dev, `dev_test_split_v2.json`, clean twin 포함)
| 실행 | 모델 | ax_review_to_ok | 예상 시간 |
|---|---|---|---|
| Q (빠른 검토) | A.X 8082 | 켬 | 약 10분 |
| P (정밀 검사) | EXAONE 8083 | 끔 | 약 35분 |

- 조항별 결과를 `out\relax_Q_rows.jsonl`, `out\relax_P_rows.jsonl`로 저장한다.
  - 필드: doc_id, segment_id, 정답 label, 문서가 깨끗한지(is_clean_doc), 최종 판정, 모델 원래 판정, needs_fact, 그 needs_fact가 카드 `blocking_if` 사실인지, review_source(needs_fact / no_evidence / quote_mismatch / 모델 자체 / 파싱 실패), 고른 카드
- 끝나면 EXAONE을 띄워 둔다.
- 조항 단위 지표(경고 포착, 오탐, 과잉 경고)가 FIX_ROUND1 D1·D4와 비슷한지 먼저 확인한다. 크게 다르면 원인을 적는다.

## 2. 새로 돌리지 않고, 저장한 결과로 문서 판정만 다시 계산
문서 판정 규칙(지금):
- 위반·위험 ≥1 → "고칠 조항 있음"
- 확인 필요 ≤ K → "큰 문제 없음" (지금 K=2)
- 그 밖 → "확인할 부분 있음"

아래 완화 방법을 Q, P 각각에 적용한다.
- **R0 (지금):** 모든 확인 필요를 센다. K=2
- **R1 (종류 분리):** 아래 확인 필요는 문서 판정 개수에서 **빼고** "직접 확인할 것" 목록으로만 보낸다. K=2
  - needs_fact가 `blocking_if` 사실이 **아닌** 것(계약서로 알 수 없는 사실)
  - review_source가 no_evidence인 것(근거 못 찾음)
  - review_source가 quote_mismatch인 것(인용 불일치)
  - 조항 판정 자체는 바꾸지 않는다. 문서 판정에서만 뺀다.
- **R2 (기준 숫자 곡선):** R0과 R1 각각에서 K = 0, 1, 2, 3, 4, 5, 6, 8, 10일 때를 계산한다.

## 3. 표
각 (모델, 방법, K)마다 아래를 낸다. 비율 옆에 분자/분모와 95% 신뢰구간(Wilson)을 붙인다.
- **깨끗한 계약서 통과율:** 깨끗한 계약서 중 "큰 문제 없음"
- **독소 계약서 경고율:** 독소 있는 계약서 중 "큰 문제 없음"이 **아닌** 것
- **독소 계약서 놓침:** 독소 있는 계약서인데 "큰 문제 없음"이 나온 doc_id 목록과, 그 문서의 독소 조항이 받은 판정

그리고 정리할 것:
- **추천 기준:** 독소 계약서 경고율이 100%(놓침 0)인 조건 중에서 깨끗한 계약서 통과율이 가장 높은 (방법, K). 모델별로 고른다.
- **깨끗한 계약서별 남은 "확인 필요":** 조항 앞 40자, 카드, review_source. R1 적용 후 기준이다.

## 4. 주의
- K는 개발용 데이터로 고르는 것이다. 고른 K는 나중에 test에서 그대로 쓰고 다시 바꾸지 않는다.
- 근로 dev는 깨끗한 계약서 7장, 독소 계약서 10장뿐이다. 숫자가 크게 흔들릴 수 있으니 신뢰구간을 꼭 붙인다.
