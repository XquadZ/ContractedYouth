# 3차 작업 (FIX_ROUND3) — FIX_ROUND2를 대신한다

`CLAUDE.md` 규칙을 따른다. A→B→C→D를 순서대로 하고, D가 끝나면 **멈춘다.** 단계마다 `docs\PROGRESS.md`에 기록한다. 실행 전 확인 질문 없이 끝까지 간다. 단, 전체가 5시간을 넘을 것 같으면 묻는다.
- **dev만** 쓴다(`dev_test_split_v2.json`, clean twin 포함, 깨끗한 계약서는 clean_v2 정의: toxic 0 그리고 check 0). test는 돌리지 않는다.
- 기본 모델은 EXAONE(8083)이다. `ax_review_to_ok` 끔, NUM2WAY 켬. A.X는 비교용으로 D에서만 돌린다.
- 판정 프롬프트(`judge.txt`)는 고치지 않는다. 카드, verify, 숫자 규칙만 고친다.
- 모든 실행은 QUANT_FULL처럼 원래 출력을 저장하고(`out\quant3\`), 변형은 replay로 계산한다.

## A. 저장된 결과로 바로 할 수 있는 수정 (replay, LLM 호출 없음)
QUANT_FULL rows로 계산하고, 켬/끔을 비교한다.
1. **숫자 규칙 표현 보강:** 최저임금 규칙이 "시급", "시간급", "시간당", "1시간당", "시간 단위 임금"을 모두 인식하게 한다. 월급은 1주 소정근로시간과 함께 환산한다. 인식 못 한 임금 조항 수를 전/후로 센다.
2. **인용 대조 완화:** 공백, 문장부호, 따옴표, `{{자리표시}}`, 조문 번호 표기 차이("제2조제1항" = "제2조 제1항")를 무시하고 비교한다. quote_mismatch 수를 toxic/safe별로 전/후로 센다.
3. **결과:** 두 수정 각각과 둘 다 켠 경우를 3장 지표 전부로 낸다(신뢰구간 포함). 정답 toxic 판정이 바뀐 건은 목록으로 따로 낸다.
4. 좋아지는 수정만 남기고(독소 계약서 놓침 0 유지가 조건), 코드에 반영한다(백업 규칙).

## B. 기준 카드 만들기·보강 (도메인별, 항목별)
공통 규칙(근로 때와 같다):
- 기준마다 `[법]`/`[표준]`/`[미확인]` 출처
- 카드 하나 500자 이내
- `uses_facts` / `blocking_if` 구분
- 라벨 기준(toxic = 조문 직접 위반 / check = 바깥 사실에 따라 달라짐)과 일치
- **정답 데이터 문장 사용 금지.** 카드는 법령·표준계약서를 보고 쓴다. 정답 데이터는 코드 목록 대조에만 쓴다.

1. **임대 카드** `criteria\LEASE_GUIDE.md`, `criteria\LEASE_cards.yaml`
   - FIX_ROUND2 C장의 시나리오별 조문 표를 법령 원문으로 확인해서 각 카드의 `basis`로 넣는다.
   - 판정에 넘기는 근거 = 검색 상위 3개 + 고른 카드 basis(중복 제거, 최대 3개 추가). 의도적인 설계 변경이므로 기록한다.
2. **차용 카드** `criteria\LOAN_GUIDE.md`, `criteria\LOAN_cards.yaml`
   - 표준 양식이 없으므로 먼저 민법 제598~608조, 이자제한법·최고이자율 규정, 보증인 보호를 위한 특별법, 민법 제428조의2·3으로 "표준형 차용증 항목표"를 만든다.
   - 항목: 당사자, 원금, 이자율(연 20% 상한), 지연이자, 변제기, 변제 방법, 기한이익 상실, 보증(서면·최고액·기간), 담보, 특약
3. **근로 카드 보강:** FIX_ROUND2 B장대로 `safe` 줄을 구체화한다. QUANT_FULL의 `clean_fail_EXAONE.csv`에서 막힌 조항의 **유형**을 보고 쓴다.
4. **"평범한 조항" 카드:** 도메인마다 1장(`LAB-GENERAL`, `LEASE-GENERAL`, `LOAN-GENERAL`)
   - safe: 권리를 빼앗거나 의무·비용을 더하지 않는 조항은 근거 조문이 없어도 "문제 없음"
     - 예: 서로 협의한다, 회사·임대인이 무엇을 제공한다, 업무·장소·날짜를 적기만 한다, 법령에 따른다
   - violation / check_if: 한쪽만 정하거나 바꿀 수 있음, 포기·면제·배상·공제·위약, 일방 통보, 기간 단축 → 이런 단어가 있으면 이 카드를 쓰지 않는다
   - **다른 카드가 하나도 맞지 않을 때만** 고른다.
   - 이 카드가 고른 조항 중 정답 toxic이 있었는지 꼭 센다.
5. **카드 점검:** 도메인별 카드 수, 최장 글자 수, 정답 toxic_code가 모두 어느 카드에 걸리는지 표(코드명만 보고).
