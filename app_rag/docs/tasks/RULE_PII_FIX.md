# RULE_PII_FIX — 최저임금·개인정보·이자율 규칙 버그 수정

## 0. 배경

외부 점검에서 아래 버그가 보고되었다. Claude가 서버 코드를 직접 실행해 **모두 재현했다.**

**중요:** 서비스 설정 `num2way=True`(`rag/settings.py`)는 숫자 검사가 모두 통과하면 모델의 위반·확인 필요를 '문제 없음'으로 바꾼다. 그래서 A는 모델이 맞게 잡은 최저임금 위반을 **지워 버릴 수 있다.** A를 가장 먼저 고친다.

## 1. 지켜야 할 것

- 고치기 전 파일은 `*_v숫자.py` / `*_v숫자.js`로 백업한다. 파일 삭제 금지.
- 검색·모델 설정(상위 3, RRF k=60, 하한 0.016, 프롬프트, 판정 기준표, `-c`, `-np` 등)은 **바꾸지 않는다.**
- **llama-server(8083)는 재시작하지 않는다.** 코드 반영은 uvicorn(8091)만 재시작한다. 재시작 전에 8091 프로세스가 1개인지 확인한다.
- 키 값(LAW_OC, HF_TOKEN, OPENAI_API_KEY, 관리자 비밀번호 등)을 출력하지 않는다.
- 판정 기준표(`criteria/`)와 법령 데이터(`corpus/`) 파일은 수정하지 않는다. 수정 전후 해시를 보고한다.
- "통과"라고만 쓰지 않는다. 항목마다 **입력 문장 → 실제 출력 원문**을 붙인다.

## 2. 수정 내용

### A. 최저임금 (월급 → 시급)

1. 월 환산 시간 = (1주 소정근로시간 + 주휴시간) × (365 ÷ 7 ÷ 12), 소수점 첫째 자리에서 반올림한다.
   - 주휴시간: 1주 소정근로시간이 15시간 이상이면 `min(8, 1주 소정근로시간 ÷ 40 × 8)`, 15시간 미만이면 0.
   - 확인: 주 40시간 → 209시간. 주 20시간 → 104시간 (20 + 4 = 24 × 4.345 = 104.3).
2. 계약서에 "주휴수당 별도 지급"처럼 월급에 주휴수당이 빠졌다고 적혀 있으면 주휴시간을 더하지 않는다. 이 경우는 `facts`에 근거 문장을 남긴다.
3. `weekly_hours_formula`에 계산식을 그대로 남긴다. 예: `(40 + 주휴 8) × 4.345 = 209시간`

### A2. 휴게시간

- `휴게 12:00~13:00`, `휴게시간 12시~13시`, `휴게 1시간`, `휴게 60분`을 모두 분으로 읽는다.
- 확인: "09:00~18:00 (휴게 12:00~13:00), 주 5일" → 주 40시간.

### B. 개인정보 마스킹

1. **주민등록번호:** 다음을 모두 `앞6자리-*******`로 가린다.
   - `900101-1234567`, `900101 - 1234567`, `900101 1234567`, `9001011234567`
   - 13자리 붙여 쓴 경우와 공백으로 나눈 경우는 오탐을 막기 위해 앞 6자리가 올바른 날짜(월 01~12, 일 01~31)이고 7번째 자리가 1~8일 때만 가린다.
   - 앞뒤에 다른 숫자가 붙어 있으면 가리지 않는다.
2. **계좌번호:** 날짜 보호 정규식과 `_looks_like_date_fragment`에 앞뒤 숫자 경계(`(?<!\d)`, `(?!\d)`)를 넣는다. 더 긴 숫자열 안의 일부가 날짜로 잡히지 않게 하는 것이다.
   - 은행 이름(국민, 신한, 우리, 하나, 농협, 기업, 카카오뱅크, 토스뱅크, SC제일, 우체국, 새마을, 신협 등)이 바로 앞에 있으면 계좌로 본다.
3. **이름:** `역할어 + 공백 + 이름 + 공백 + 항목명`도 가린다.
   - 항목명: 주민등록번호, 주민번호, 생년월일, 주소, 연락처, 전화, 휴대폰, 계좌
   - 예: `채무자 이기성 주민등록번호` → `채무자 이** 주민등록번호`
   - 성씨 목록 검사는 지금 규칙을 그대로 쓴다.
4. 가린 개수(`counts`)에 새로 가린 것도 들어가게 한다.

### C. 이자율 읽기

1. 이자 표현을 넓힌다.
   - 주어: 이자, 이자율, 이율, 연이율, 약정이율, 금리
   - 조사·기호: 은, 는, 이, 가, 를, :, ：, 없음
   - 단위: %, 퍼센트
   - 예: `이자는 연 25%`, `이율: 연 25%`, `연 25%의 이자`, `금리는 연 25퍼센트`
2. **월 이율·일 이율:** `월 3%`는 연 36%(×12), `일 0.1%`는 연 36.5%(×365)로 환산한다.
   - 괄호로 연 이율이 함께 적혀 있으면(`월 3%(연 36%)`) 적힌 연 이율을 쓴다. 둘이 다르면 큰 값을 쓰고 `facts`에 둘 다 남긴다.
   - `interest_rate_basis`(year/month/day/amount)를 기록한다.
3. **금액으로 적은 이자:** 원금과 주기별 이자 금액이 함께 있으면 연 이율 = 주기 이자 × 연간 횟수 ÷ 원금 으로 계산한다.
   - 원금: `원금`, `차용금`, `대여금`, `빌린 돈`, `일금`, `금 … 원정`, `₩숫자`
   - 주기: 매월, 매달, 매주, 매년
   - **한글 금액**을 숫자로 바꾸는 함수를 추가한다. 예: 일십만원 → 100,000 / 이천만원 → 20,000,000 / 칠천만원 → 70,000,000 / 삼백오십만원 → 3,500,000. `₩숫자`나 아라비아 숫자가 함께 있으면 숫자를 우선한다.
   - 확인: `일금 이천만원(₩20,000,000) 차용하여 매월 일십만원씩 이자를 상환한다` → 연 6%, '문제 없음'.
4. 판정: 계산된 연 이율이 계약일 기준 최고이자율을 넘으면 위반이다. 상한 값은 지금처럼 버전 선택(`select_versions`)으로 정해지는 값을 쓰고, 새로 하드코딩하지 않는다.

### D. 화면 표시

1. 이자 관련 근거로 「이자제한법 제2조」를 보여 줄 때, 법령 데이터에 이미 있는 「이자제한법 제2조제1항의 최고이자율에 관한 규정」(연 20%)을 **함께** 붙여 보여 준다. 검색 설정은 바꾸지 말고, 표시 단계에서 붙인다.
2. `static/review.js`
   - 131행 "검증을 통과한 corpus 근거입니다." → "법령 원문에서 확인한 근거입니다."
   - 725행 "검증된 corpus 근거" → "검증된 법령 근거"
   - 그 밖에 사용자 화면에 보이는 영어 내부 용어(corpus, fact, segment 등)가 있으면 목록으로 보고만 한다(고치지 말 것).
