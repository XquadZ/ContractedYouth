# MVP: 내 PDF·HWP를 넣으면 같은 화면에서 실제 분석

WORK = C:\Users\DMLAB_Server1\Contracted_Youth\app_rag
목표: 샘플 화면은 그대로 두고, **사용자가 자기 파일을 넣으면 같은 화면 틀에 실제 RAG+A.X 결과가 나오게** 한다.

## 0. 원칙
- 바꿀 파일은 `*_v숫자`(아직 없는 이름)로 백업 후 수정. 파일 삭제 금지.
- A.X 설정, 검색 설정(상위 3, 하한, RRF), 판정 프롬프트는 바꾸지 않는다.
- **사용자 파일과 원문은 디스크·로그에 저장하지 않는다.**
  - 메모리에서만 처리한다.
  - 로그에는 조각 수·시간·판정 수·근거 ID만 남긴다.
  - 임시 파일이 꼭 필요하면 처리 직후 지우고, 그 코드 줄을 보고한다.
- 외부 API 금지.
- 결과마다 명령·출력·스크린샷(`out\mvp_upload\*.png`)을 붙인다. "완료/통과/✓"만 쓰지 않는다. 못 한 것은 "미확인"으로 쓴다.

## 1. 파일 → 텍스트 (`rag/extract.py`, `POST /api/extract`)
- **PDF:** PyMuPDF(`fitz`)로 페이지별 텍스트를 뽑는다.
  - 전체 글자 수가 페이지당 50자 미만이면 스캔본으로 본다. 화면에 "글자를 읽을 수 없는 PDF(스캔본)예요. 텍스트로 된 PDF나 HWP를 올려 주세요."를 띄운다.
  - OCR은 하지 않는다.
- **HWP:** `hwp5txt`(pyhwp). 지난번 표준근로계약서 추출에서 됐던 방식이다.
- **HWPX:** zip 안의 `Contents/section*.xml`에서 텍스트를 뽑는다.
- **TXT:** 그대로 쓴다.
- 응답: `{"pages":[{"page":1,"text":"…"}], "chars":N, "kind":"pdf|hwp|hwpx|txt", "scanned":false}`
- 표가 많은 양식(표준계약서)은 칸 순서가 섞일 수 있다. 표준근로계약서 hwp, 주택임대차표준계약서 hwpx 1장, 아무 PDF 1장으로 뽑은 결과의 앞 500자를 보고서에 붙인다.
- 파일 크기 상한은 10MB로 하고, 넘으면 안내한다.

## 2. 입력 진입점
- 왼쪽 "+ 내 PDF 열기"를 "+ 내 계약서 열기 (PDF·HWP·HWPX·TXT)"로 바꾼다.
- "텍스트 붙여넣기" 버튼을 하나 더 둔다.
- 파일을 고르거나 붙여넣으면 → `/api/extract` → **종류 확인 단계** → `/api/analyze` 순서로 간다.
- 분석 중에는 진행 표시를 띄운다. 조항 수와 지금 몇 번째 조항인지를 보여 준다.
  - 서버가 진행을 못 알려 주면 "분석 중(조항 n개, 약 m초 예상)"만 표시한다. 예상 시간은 dev 평가의 조각당 평균 시간으로 계산한다.
- 왼쪽 "내 계약서" 목록에 사용자 파일이 맨 위에 추가된다. 샘플과 구분해서 "내 파일" 표시를 단다. 새로고침하면 사라져도 된다(저장 안 함).

## 3. 계약서 종류 자동 인식 (`rag/domain.py`)
- 키워드 점수로 정한다.
  - 근로: 근로계약서, 사업주, 근로자, 임금, 근로시간
  - 임대: 임대차, 임대인, 임차인, 보증금, 차임
  - 차용: 차용증, 금전소비대차, 채권자, 채무자, 변제, 이자
- 1등 점수가 2등의 1.5배 미만이거나 키워드가 거의 없으면 사용자에게 고르게 한다.
- 화면에 "근로계약서로 인식했어요 [바꾸기]"를 띄운다. 사용자가 바꾸면 그 종류로 분석한다.
- 우리 범위 밖(예: 매매계약서)으로 보이면 "지금은 근로·임대차·차용 계약서만 분석해요."라고 안내한다.
- 테스트: 세 도메인 dev 계약서 각 3장과 샘플들로 인식 결과 표를 낸다.

## 4. 같은 화면 틀에 실제 결과 그리기
- 샘플이 쓰는 화면 컴포넌트(채팅 요약, 원본 뷰어, 오른쪽 탭 4개, 위험 카드)를 그대로 쓰고, 데이터만 `/api/analyze` 결과로 채운다.
- `report.json` 필드 → 카드 칸 대응표는 UI_AUDIT 2장 표를 따르고, 바꾼 대응을 보고서에 적는다.
- **근거 칸:** 검증을 통과한 corpus 근거만 보여 준다. 조문 원문 인용과 출처 꼬리표 `[법령]` 등을 붙인다. 근거가 0개면 "근거를 찾지 못해 직접 확인이 필요해요"라고 표시한다.
- **원문 하이라이트:** 고정 % 좌표가 아니라, 조각 텍스트를 추출한 페이지 텍스트에서 찾아 그 위치에 표시한다.
  - PDF는 PyMuPDF `search_for`로 좌표를 구한다. 처음 30자로 찾고, 못 찾으면 15자로 다시 찾는다.
  - HWP·TXT는 원본 뷰어 대신 텍스트 뷰어에 하이라이트한다.
  - 찾은 비율(찾은 조각 / 전체 조각)을 보고서에 적는다.
- **채팅 입력창:** 사용자 파일 화면에서는 자유 질문을 A.X로 보내지 않는다. 입력창 위에 "안내 도우미: 결과 안의 내용만 보여줘요(AI 답변 아님)"를 표시한다. 버튼(필수 조항 확인, 위험 조항 검토)은 결과 데이터로 동작하게 둔다.
- **리포트 저장:** 사용자 결과도 지금 .txt 저장이 그대로 되게 한다.

## 5. 샘플 쪽 정리 (지우지 않음)
- 샘플 화면 상단에 "예시 화면" 배지를 단다.
- 샘플 카드의 출처 문구 "A.X 검색 근거"는 "예시 설명"으로 바꾼다.
- 샘플에 나오는 corpus 밖 조문(민법 제618·397·568·580조, 민간임대주택법 제49조, 같은 법 시행령 제38·40조 등)에 "근거 자료 밖 조문(참고)" 표시를 단다.
- (선택) 시간이 되면, 주택임대차·근로 샘플 텍스트를 실제 `/api/analyze`로 한 번 돌린 결과를 `samples\*_result.json`으로 저장해 둔다. 그러면 샘플도 "미리 돌려 둔 실제 결과"로 보여 줄 수 있다. 원본 고정 데이터는 그대로 두고, 바꿀지는 내가 정한다.
