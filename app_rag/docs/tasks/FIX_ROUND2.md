# 2차 작업 (FIX_ROUND2)

`CLAUDE.md` 절대 규칙을 따른다. A→B→C를 순서대로 하고 C가 끝나면 **멈춘다.** 단계마다 `docs\PROGRESS.md`에 "FIX_ROUND2-A" 같은 제목으로 기록한다.
- 평가는 `datasets\splits\dev_test_split_v2.json`의 **dev만** 쓴다. clean twin을 포함한다. test는 돌리지 않는다.
- 단계 하나가 90분을 넘을 것 같으면 실행 전에 예상 시간을 적고 묻는다.

## 결정 사항 (사용자와 합의)
- 판정 기본 모델: **EXAONE 4.0 32B Q4_K_M** (8083, reasoning off, ctx 8192, 다른 생성 설정은 A.X와 같게)
- `ax_review_to_ok`: **끔** (FIX_ROUND1 D3에서 독소 7건을 지웠다)
- A.X(8082)는 비교용으로 남긴다. 설정은 바꾸지 않는다.
- EXAONE과 A.X는 동시에 못 올린다. 평가할 때는 지금처럼 하나씩 띄운다. 작업이 끝나면 **EXAONE을 띄워 둔다**(이제 기본 모델이므로).

## A. 기본 모델 전환 + 조항별 결과 저장 + 깨끗한 문서 분석
1. **기본 모델 전환:** `rag\paths.py` 등에서 판정 모델을 설정으로 고를 수 있게 하고, 기본값을 EXAONE으로 한다. 서버(8091)도 EXAONE을 쓰게 한다. 백업 규칙을 지킨다.
2. **조항별 결과 저장:** 모든 평가 스크립트가 조항별 결과를 `out\<실행이름>_rows.jsonl`로 저장하게 한다. 정답 데이터라 원문 저장이 괜찮다.
   - 필드: doc_id, segment_id, split, 정답 label, gold_codes, 모델 원래 판정, 최종 판정, 바뀐 이유(review_source), 고른 카드, needs_fact, 근거 ID, why, 지연 시간
3. **근로 dev를 EXAONE(새 기본 설정)으로 한 번 돌린다.** 이게 2차 기준점(R2-0)이다. 예상 약 35분.
4. **깨끗한 문서 분석:** "큰 문제 없음"이 안 나온 깨끗한 문서마다 막은 조항을 표로 낸다.
   - 열: doc_id, 조항 앞 60자, std_item, 판정, 고른 카드, needs_fact, review_source
   - 그다음 막힌 조항을 **유형별로** 센다. 예: 카드 없음 / 카드의 safe에 맞는데 확인 필요 / needs_fact가 사실표에 있는데 확인 필요 / 근거 0개 / 인용 불일치
   - 안전 조항 과잉 경고도 같은 유형표로 낸다.

## B. 근로 카드의 "안전" 조건 구체화 (최대 3회)
목표 (근로 dev, EXAONE):
- 경고 포착률 ≥ 90%
- 오탐률 ≤ 5%
- 과잉 경고율 ≤ 20%
- 깨끗한 문서 통과율 ≥ 5/7

고치는 방법은 A-4 유형표의 큰 순서대로 한다.
- **카드의 `safe` 줄을 구체화한다.** 막힌 조항의 **유형**을 보고 쓴다.
  - 예: "근무장소가 주소·점포명으로 적혀 있고 변경 문구가 없으면 안전"
  - 예: "4대보험 가입을 적었으면 안전(가입 비율·실제 신고 여부는 묻지 않음)"
- **정답 문장을 그대로 베끼지 않는다.** 정답 데이터 문장을 카드에 넣지 않는다.
- **카드 매칭이 안 돼서 막힌 조항은 `match_keywords`를 보강한다.**
- **판정 프롬프트(`judge.txt`)는 이번에 고치지 않는다.** 카드와 verify만 고친다.
- 시도마다 R2-1, R2-2, R2-3으로 전/후 표를 낸다. 지표 전부, 신뢰구간 포함.
- 3회 안에 목표를 못 넘으면 가장 나은 버전을 남기고 멈춘다. 그리고 유형표와 다른 방향 제안을 적는다.

## C. 임대 기준 카드 + 시나리오별 조문 (근로와 같은 방식)
1. **가이드:** `criteria\LEASE_GUIDE.md`
   - `tasks\CURSOR_PROMPT_LAB_GUIDE.md`와 `CURSOR_PROMPT_LAB_CARDS_FIX.md` 방식을 따른다. 기준마다 `[법]`/`[표준]`/`[미확인]` 출처를 단다.
   - 바탕: 주택임대차표준계약서(`datasets\property\source_hwpx_originals\`에서 표준 양식 1장), `data_contract\law_api\현행`의 주택임대차보호법·시행령, 민법 원문
2. **카드:** `criteria\LEASE_cards.yaml`
   - 카드마다 500자 이내
   - `uses_facts` / `blocking_if`로 나눈다
   - 라벨 기준(toxic/check)과 맞춘다
3. **시나리오별 조문:** 카드의 `basis`에 넣는다. 아래 초안을 **법령 원문으로 확인해서** 쓴다. 정답지 근거 칸을 보고 만들지 않는다.
   | 시나리오 | 조문 |
   |---|---|
   | 계약기간 2년 미만 | 주택임대차보호법 제4조 제1항 |
   | 보증금 반환·인도 | 같은 법 제4조 제2항, 제3조의2, 민법 제536조 |
   | 갱신요구권·갱신 거절 | 같은 법 제6조의3 (+제6조, 제6조의2) |
   | 차임·보증금 증액 | 같은 법 제7조, 시행령 제8조 |
   | 전입신고·확정일자 | 같은 법 제3조, 제3조의2 |
   | 수선·무단출입·사용 방해 | 민법 제623조 (형법 제319조는 미수집 → `missing_basis`) |
   | 원상복구·통상 손모 | 민법 제615조, 제654조 |
   | 차임 연체 해지 | 민법 제640조 |
   | 위약금·손해배상 예정 | 민법 제398조 |
   | 임차인에게 불리한 약정 | 같은 법 제10조 |
   | 관리비 | 맞는 조문 없음 → check 조건으로만 |
4. **검색 연결 (의도적인 설계 변경, 전/후 기록):**
   - 판정에 넘기는 근거 목록 = 검색 상위 3개 + 고른 카드의 `basis` 조문(중복 제거, 최대 3개 추가)
   - 검색 상위 3개와 하한 0.016은 그대로 둔다.
   - verify의 "근거 ID는 넘겨준 목록 안에서만" 규칙은 합친 목록 기준으로 한다.
5. **판정 프롬프트:** 카드 지시 줄이 임대에도 들어가게 한다. FIX_ROUND1-C에서 "카드 있을 때만"으로 바꾼 줄은 이제 임대에 카드가 있으므로 적용된다.
6. **임대 dev를 EXAONE으로 돌린다.**
   - L0: 카드 없음(= FIX_ROUND1 BASE와 같은 조건을 EXAONE으로)
   - L1: 카드 + 근거 연결
   - 예상 시간이 길면(임대 dev 조각 약 390개) 먼저 묻는다.
   - 지표 전부를 내고, recall@3(검색만)과 근거 일치율(최종)을 나눠 낸다. 깨끗한 문서 분석 표(A-4 형식)도 낸다.
