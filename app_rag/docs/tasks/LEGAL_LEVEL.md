# LEGAL_LEVEL — 이 서비스가 어느 수준의 도움을 주는지 분석

## 0. 목적

발표에서 "이 서비스로 어느 정도 수준의 법률 도움을 받을 수 있나"를 숫자로 답하려고 한다. 지금까지는 "독소조항을 몇 % 잡았나"만 있다. 아래 세 가지를 추가로 본다.

- 어떤 종류의 조항은 확실히 잡고, 어떤 종류는 놓치는지
- 보여 준 근거 조문이 맞는지
- 설명과 수정 문구가 쓸 만한지

**원칙**
- **A~C는 이미 돌린 시험 결과만 다시 집계한다.** 모델을 다시 부르지 않는다.
  - 대상: `out/quant_test/EXAONE_tuned_{LAB,LEASE,LOAN}_rows.jsonl`
  - 판정 기준: `freeze.json`의 `fixed` 설정으로 `eval/final_test_analyze.py`의 `apply_settings`를 적용한 판정. 발표 수치와 같은 기준이다.
- **D만 모델을 부른다.** 서비스에 PDF를 실제로 올린다.
- 시험 결과를 보고 규칙·기준표·프롬프트를 고치지 않는다. 이번 작업은 기록용 분석이다.
- 하이퍼파라미터와 설정을 바꾸지 않는다. llama-server를 재시작하지 않는다. 파일을 삭제하지 않는다. 키 값을 출력하지 않는다.
- 모든 표에 분모를 같이 적는다. n이 5 미만인 칸은 "표본 적음"으로 표시한다.

## A. 유형별 탐지력: 어떤 조항을 잘 잡나

1. 정답이 toxic인 조항을 `gold_codes`(독소 유형 코드)별로 묶는다. 유형 이름은 각 분야 `02_법률근거` 파일의 `violation_name`을 쓴다.
2. 유형마다 아래 값을 낸다.
   - n
   - 위반·위험 비율
   - 확인 필요 비율
   - 문제 없음(놓침) 비율
3. 유형을 세 등급으로 나눈다.
   - **확실히 잡음:** 위반·위험 ≥ 70%
   - **경고는 함:** 위반·위험 < 70%, 위반·위험·확인 필요 합계 ≥ 80%
   - **놓치는 편:** 위반·위험·확인 필요 합계 < 80%
4. 등급별로 어떤 성격의 조항인지 한 줄로 적는다. 예: "숫자로 판단하는 조항(최저임금, 이자율)", "금지 문구가 분명한 조항", "해석이 필요한 조항".
5. 정답이 check인 조항도 같은 방식으로 따로 표를 만든다.

## B. 근거 조문 일치

1. 정답이 toxic이고 모델이 위반·위험·확인 필요를 붙인 조항을 대상으로 한다. 사용자 화면에 나간 근거는 `evidence_final`이다.
2. 근거 중 하나라도 정답 근거 조문(`gold_provisions`)과 같은 조문이면 일치로 센다.
   - 같은 조문 = 법령 이름과 조 번호가 같음. 항은 무시한다. "제428조의2"처럼 '조의'는 구분한다.
   - **매칭 규칙을 코드로 보여 주고**, 정규화 전과 후의 예시 10쌍을 보고한다.
3. 분야별로 아래 값을 낸다.
   - 근거 일치율
   - 근거 0개 비율
   - 근거는 있지만 정답과 다른 비율
4. 불일치 사례 10개를 원문과 함께 보고한다. 조항, 모델 근거, 정답 근거를 나란히 보여 준다.
5. 정답 근거 조문이 우리 법령 자료(corpus)에 아예 없는 경우는 "자료 없음"으로 따로 센다. 검색이 찾을 수 없었던 경우이기 때문이다.

## C. 설명·수정 문구 검토표 (사람이 채움)

1. A의 대상 중 seed 42로 30개를 뽑는다. 분야별 10개다.
2. CSV `out/legal_level/review_sheet.csv`를 만든다. 열은 다음과 같다.
   - 분야, doc_id, segment_id, 조항 원문
   - 모델 판정, 모델 설명(why), 모델 수정 문구(suggestion), 모델 근거 조문 제목
   - 정답 유형 이름, 정답 설명(why), 정답 수정 예시(suggested_revision), 정답 근거 조문
   - 빈 칸 4개: `판정_맞음`, `이유_맞음`, `근거_맞음`, `수정문구_문제해소` (Y / N / 애매)
3. 빈 칸은 채우지 않는다. 팀원이 채운다.
4. 채운 뒤 집계하는 스크립트 `eval/legal_level_tally.py`도 만들어 둔다. 지금은 빈 시트로 실행해서 동작만 확인한다.

## D. 실제 서식 PDF 15장 전체 확인 (모델 호출)

1. 대상은 `datasets/test_hwp_pdfs_v4_claude/`의 PDF 15장이다. 독소 9장, 정상 6장이다.
2. 현재 서비스 코드로 `/api/extract` → `/api/analyze`를 실행한다. 사용자 계정을 쓴다.
3. 파일마다 아래를 보고한다.
   - 점수, 등급, 걸린 시간
   - 판정 카드 수: 위반 / 위험 / 확인 필요
4. 정답과 비교한다. 정답은 각 파일 manifest의 segment별 label이다.
   - 독소 문서: '안전'이 아닌지 확인한다.
   - 정상 문서: '안전'인지 확인한다.
   - 정답 toxic 조항 중 서비스가 경고를 붙인 비율
   - 정답 safe 조항 중 위반·위험으로 잘못 판정한 비율
5. 이 결과는 시험 이후 규칙을 고친 **현재 서비스** 기준이다. 보고서에 그렇게 명시한다.
6. 예상 시간은 약 40분이다. 1시간을 넘기면 멈추고 그때까지의 결과를 보고한다.
