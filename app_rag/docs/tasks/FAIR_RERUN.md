# 공정 재실험 (FAIR_RERUN)

**왜 다시 하나:** 지난 GPT 실험 두 번(`out\quant_gpt\`, `out\quant_neutral\`의 gpt-4o-mini·gpt-4.1)은 모델마다 입력이 달라서 공정하지 않았다.
1. 개인정보 가리기(`rag\pii.py`)가 일반 단어를 가렸다. 갑·을의 "을"을 이름 앞 역할어로 보고, 조사 "을" 뒤에 오는 단어까지 가렸다.
   - 예: "신청을 제한하지 않는다" → "신청을 제*** 않는다"
   - dev 799조각 중 **266개**가 바뀌었다.
2. GPT 경로는 **프롬프트 전체**(법 조문·카드 포함)를 가렸다(`rag\llm_router.py` 147행, `eval\quant_gpt_run.py` 176행). 예: "주민등록을 마친" → "마*"
3. 로컬 모델은 원문을 받았다. 메시지도 GPT에만 system 문장이 하나 더 있었다.

그래서 이 문서대로 **모든 모델이 똑같은 입력을 받는 조건**에서 다시 돌린다.
- `NEUTRAL_CARDS.md`의 GPT 부분은 이 문서로 대체한다.
- 이전 GPT 결과는 지우지 않고 참고로만 남긴다. 비교에는 쓰지 않는다.

`CLAUDE.md` 규칙을 따른다.
- dev만 쓴다(`dev_test_split_v2.json`, clean twin, clean_v2). test는 돌리지 않는다.
- 파일은 지우지 않는다. 고칠 파일은 `*_v숫자.py`로 백업한다(이미 있는 이름이면 다음 숫자).
- 결과는 새 폴더 `out\quant_fair\`에 둔다.

## 0. 시작 전 (사용자는 자고 있다 — 끝까지 묻지 않고 진행한다)
- 지금 `NEUTRAL_CARDS` 실행(EXAONE·A.X 중립)이 돌고 있으면 **끝날 때까지 기다린다.** 중간에 끊지 않는다. 그동안은 코드도 고치지 않는다.
- 끝났다는 기준: `out\quant_neutral\AX_LOAN_rows.jsonl`이 있고, `neutral_run.py` 프로세스가 없다.
  - 10분마다 확인한다(짧은 sleep 명령을 반복).
  - 4시간을 기다려도 안 끝나면 그 상태를 기록하고, GPU를 쓰지 않는 2단계와 3-1(GPT)만 한 뒤 보고서를 쓰고 멈춘다.
- 끝나면 1단계부터 한다.
- 사용자에게 묻지 않는다. 멈춰야 할 상황은 맨 아래 "묻지 말고 이렇게 한다" 표대로 처리한다.

## 2. 가리기 고치기 (돈 안 듦)
### 2-1. 고치기 전에 기록
- 지금 코드로 로컬 경로의 프롬프트(중립·튜닝, 799×2개)를 만들어 해시를 `out\quant_fair\prompt_hash_before.json`에 저장한다. 3단계의 재사용 판단에 쓴다.

### 2-2. 고칠 것
- 백업: `pii_v1.py`, `llm_router_v1.py`, `quant_gpt_run_v1.py`, `quant_run_v1.py` 등
- 이름 규칙:
  - `성명`·`이름` 뒤의 2~4글자 한글은 가린다(콜론이 있든 없든).
  - 역할어(임대인·임차인·사업주·근로자·대표자·채권자·채무자·보증인·갑·을) 뒤의 이름은 **콜론(`:` 또는 `：`)이 있을 때만** 가린다.
  - 역할어 바로 앞에 한글이 붙어 있으면 역할어로 보지 않는다. 예: "신청을"의 "을"
- 가리는 범위: **계약서 조각과 그 조각에서 뽑은 facts만** 가린다.
  - 프롬프트 전체에 `mask_pii`를 거는 코드(`llm_router.py`, `quant_gpt_run.py`)는 뺀다.
  - 서비스(`pipeline.py`)는 지금처럼 업로드 직후에 가린다. 고친 규칙이 적용된다.

### 2-3. 테스트 추가
정답 데이터 문장은 쓰지 않는다. 문장은 직접 만든다.
- **바뀌면 안 되는 문장** 10개 이상. 예:
  - "갑은 을의 신청을 제한하지 않는다."
  - "임금은 을에게 지급한다."
  - "근로자 대표와 협의한다."
  - "임차인 주거 안정을 고려한다."
  - "보증금은 갑이 보관한다."
- **가려야 하는 문장:** "성명: 홍길동", "임대인: 김철수", "을 : 이영희", "이름 박민수". 기존 21개 테스트(전화·주민번호·계좌·이메일·주소)는 유지한다.

### 2-4. 통과 기준 (GPT 돈 쓰기 전)
- dev 799조각 전부에 고친 가리기를 돌린다. 바뀐 조각 수와 **바뀐 곳 전부(전/후)**를 `out\quant_fair\mask_check.md`에 적는다.
  - 옛 가리기로 바뀐 수(266)와 나란히 적는다.
  - 바뀐 곳은 모두 진짜 개인정보(이름 칸, 전화 등)여야 한다. 일반 단어가 하나라도 가려지면 고치고 다시 돌린다.
  - 3번 해도 안 되면 멈추고 묻는다.
- 데모 PDF 6장(`..\datasets\demo_pdfs\*.pdf`)도 추출 → 가리기를 해서, 바뀐 곳을 같은 파일에 적는다. 파일명이 한글이라 glob으로 찾는다.
- 프롬프트 검사(`out\quant_fair\prompt_hash_after.json`):
  - 고친 뒤 GPT 경로와 로컬 경로의 user 메시지가 799×2개 모두 같은지 해시로 확인한다.
  - 프롬프트 안의 법 조문 부분이 corpus 원문과 같은지(별표 0개) 확인한다.

## 3. 실행
| 실행 | 모델 | 카드 | 처리 |
|---|---|---|---|
| L-N | luna (추론 끔) | 중립 | 새로 |
| L-T | luna (추론 끔) | 튜닝 | 새로 |

- **재사용 조건**(둘 다 만족해야 한다):
  1. 2-4에서 dev 799조각 중 가리기로 바뀐 조각이 0개
  2. `prompt_hash_before`와 `prompt_hash_after`의 중립 로컬 프롬프트 799개가 모두 같음
  - 하나라도 아니면 새로 돌린다.
- 튜닝 로컬(E-T, A-T)은 새로 돌린다. FIX_ROUND3 때의 코드와 지금 코드가 같다고 확인할 수 없기 때문이다.
- E-T(그리고 필요하면 E-N)는 60분을 넘는다. 이번에는 사용자가 미리 허락했으니 멈추지 말고 진행한다.
- GPT는 API라 GPU를 쓰지 않으므로 로컬 실행과 동시에 해도 된다. 로컬은 한 번에 한 모델만 올린다.
- 결과 파일: `out\quant_fair\{모델}_{neutral|tuned}_{도메인}_rows.jsonl`과 meta

### 3-1. GPT: luna 하나만, 가장 싸게
- **gpt-4.1, gpt-4o-mini는 부르지 않는다.** 다른 OpenAI 모델도 부르지 않는다.
- 모델 찾기: `/v1/models`에서 "luna"가 들어간 모델 ID를 찾는다(pro 제외). 공식 가격 페이지(https://openai.com/api/pricing)에서 입력·출력·Batch 가격을 찾아 적는다.
  - 목록에 없으면 100만 토큰당 입력 가격이 가장 싼 범용 모델 3개와 가격을 적고 **멈추고 묻는다.**
- 추론 끄기: `reasoning_effort`는 지원하는 가장 낮은 값으로 둔다(none → minimal → low 순).
  - temperature나 max_tokens를 받지 않는 모델이면 `max_completion_tokens=512`와 기본 temperature를 쓰고, 그 사실을 적는다.
- **시범 20조각**(중립 카드, 도메인을 섞어서)을 일반 요청으로 먼저 보낸다.
  - 조각당 입력·출력·추론 토큰을 재서 전체 비용(L-N+L-T)을 추정한다. 추론 토큰이 0이 아니면 그 수를 적는다.
  - **추정이 $1.0을 넘으면 멈추고 묻는다.** 실제 누적 비용도 $1.0에 닿으면 멈춘다.
  - 계약서 1장 처리 시간은 이 시범의 평균으로 계산한다(Batch에서는 시간을 잴 수 없다).
- 본 실행은 **Batch API**로 보낸다. 요청 내용은 일반 요청과 똑같이 만든다.
  - 2시간이 지나도 안 끝나면 취소하고, 남은 것만 일반 요청으로 보낸 뒤 그 사실을 적는다.
- 캐시: 키는 모델 ID + 요청 전체의 해시로 하고, 새 폴더 `out\quant_fair\cache\`에 둔다. 입력이 바뀌었으므로 옛 캐시는 쓰지 않는다.
- JSON 모드(json_object)는 유지한다.
  - 프롬프트에 "JSON"이라는 말이 있는지 확인한다. 없으면 JSON 모드를 끄고 로컬처럼 파싱한다(프롬프트에 말을 덧붙이지 않는다).
  - 모델마다 파싱 실패 수를 적는다.

## 4. 결과
새 파일 `eval\fair_analyze.py`로 계산한다. 채점 함수는 `neutral_analyze.py`와 같은 것(`analyze_rows`, `sweep_best`, `score_docs`, `mcnemar_compare`)을 쓴다.
- **표 1 (중립 카드), 표 2 (튜닝 카드):** 모델 3개 × 도메인 3개
  - 항목: 경고 포착 / 오탐 / 과잉 경고 / 깨끗 통과 / 독소 계약서 놓침 / 파싱 실패 / 계약서 1장 시간
  - 모델마다 두 줄: 고정 설정, 모델별 최적(고른 설정을 함께 적는다)
  - 비율 옆에 분자/분모와 95% 신뢰구간
- **표 3 (튜닝 효과):** 모델마다 중립 → 튜닝 변화량. EXAONE만 크게 좋아졌으면 "카드가 EXAONE에 맞춰졌다"고 한 줄로 적는다.
- **McNemar:** EXAONE vs luna, EXAONE vs A.X, luna vs A.X × 카드 2벌 × 도메인 3 (경고 포착, 오탐)
- **점수 공식:** 지금 공식과 "확인 필요 3개 이상이면 최대 79점" 수정안으로 각각 계산한다. 깨끗한 계약서의 안전 비율과 독소 계약서의 비안전 비율을 낸다.
- **설정 차이 표:** 모델별 temperature, 출력 한도, JSON 모드, 추론 설정, 잘린 응답 수
- **이전 GPT 결과:** "가리기 버그로 799조각 중 266개 입력이 깨짐 → 비교에서 제외"라고 한 줄 적는다.
- **비용:** 시범과 본 실행 각각, 조각당 평균 입력·출력·추론 토큰
