# 전체 정량 평가 (QUANT_FULL)

`CLAUDE.md` 규칙을 따른다. 시간은 오래 걸려도 된다(예상 2~3시간). **실행 전 확인 질문 없이 끝까지 진행한다.** 단, 5시간을 넘을 것 같으면 그때 묻는다.

## 0. 원칙
- **dev만 쓴다** (`datasets\splits\dev_test_split_v2.json`, clean twin 포함).
  - test는 돌리지 않는다. 카드·규칙을 아직 고치는 중이라, 지금 test를 쓰면 마지막에 쓸 시험지가 없어진다.
- 판정 프롬프트, 카드, 검색 설정, A.X·EXAONE 생성 설정은 바꾸지 않는다.
- **모델은 도메인마다 한 번씩만 돌린다.** 검증 규칙 변형은 저장한 원래 출력으로 **오프라인 재계산(replay)**한다. GPU 시간을 아끼기 위해서다.
- 진행 중인 RELAX_CHECK P(EXAONE, 근로)는 끝까지 둔다. 아래 1장 필드를 갖췄으면 재사용하고, 모자라면 근로도 다시 돌린다. 근로 A.X도 같은 기준으로 `relax_Q_rows.jsonl` 재사용 여부를 정한다.
- 결과마다 명령·출력 파일을 붙인다. 못 한 것은 "미확인"으로 쓴다.

## 1. 모델 실행 (2 모델 × 3 도메인 dev)
| 모델 | 포트 | 도메인 | 예상 |
|---|---|---|---|
| A.X 4.0 Light | 8082 | 임대, 차용 (근로는 재사용 가능 시 생략) | 약 25분 |
| EXAONE 4.0 32B Q4_K_M | 8083 | 임대, 차용, 근로(P 재사용 가능 시 생략) | 약 80~110분 |

- 두 모델을 동시에 올리지 않는다. 모델을 바꿀 때 **내리고 올리는 데 걸린 시간을 잰다**(7장 계산에 쓴다).
- 실행할 때 `ax_review_to_ok`는 **끈다**(원래 출력을 남기기 위해).
- `out\quant\<모델>_<도메인>_rows.jsonl`에 조항마다 저장한다.
  - doc_id, segment_id, std_item, 정답 label, gold_codes, is_clean_doc
  - 조항 텍스트(정답 데이터라 저장 가능)
  - **모델 원래 출력 JSON 전체:** verdict, contract_quote, evidence(id·quote), needs_fact, why, suggestion
  - 넘겨준 근거 ID 목록(검색 순위·점수 포함), 고른 카드, 사실표(문서 단위, 문서마다 한 번)
  - 검증 결과: 최종 verdict, review_source, notes, 버린 근거 ID, quote_mismatch 여부, 파싱 성공 여부
  - 지연 시간(ms)
- 끝나면 EXAONE을 띄워 둔다.

## 2. 오프라인 재계산 (`eval\replay.py`, LLM 호출 없음)
저장한 원래 출력에 검증 단계를 다시 적용한다. 먼저 **재현 확인**을 한다. 실행 때와 같은 설정으로 replay한 최종 판정이 저장된 최종 판정과 100% 같아야 한다. 다르면 멈추고 원인을 적는다.

조항 단위 변형:
- **AXOK:** `ax_review_to_ok` 끔 / 켬
- **NUM2WAY (숫자 규칙 양방향):** 끔 / 켬
  - 켬이면: 숫자 규칙이 조항 **자기 문장의 값만으로** 완전히 계산되고 "기준 충족"이 나왔으며, 조항에 다른 위험 단어가 없을 때만 모델의 위반·위험·확인 필요를 "문제 없음"으로 바꾼다.
  - 숫자 규칙: 최저임금(연도표), 휴게시간, 임대료 증액 5%, 이자 연 20%. 규칙마다 판단 근거 값을 notes에 남긴다.
  - 다른 위험 단어 예: 공제, 차감, 가산, 포함, 없이, 위약, 벌금, 수습, 주휴, 배상, 포기
  - 바꾼 조항 수를 정답 label별로 센다. **정답 toxic을 바꾼 건은 목록으로 따로 낸다.**
- 조합 4가지: (AXOK 끔/켬) × (NUM2WAY 끔/켬)

문서 단위 변형 (각 조항 변형 위에서):
- **R0:** 모든 확인 필요를 센다
- **R1:** 계약서로 알 수 없는 needs_fact(blocking_if 아님), no_evidence, quote_mismatch로 생긴 확인 필요는 문서 개수에서 빼고 "직접 확인할 것"으로 보낸다(조항 판정은 유지)
- **K:** 0, 1, 2, 3, 4, 5, 6, 8, 10

## 3. 지표 (모델 × 도메인 × 변형마다, 95% Wilson 신뢰구간과 분자/분모)
조항 단위:
- 탐지율(위반·위험), 경고 포착률(+확인 필요), 놓침률
- 오탐률, 과잉 경고율
- check 정답률(확인 필요)
- 독소 코드별 경고 포착 표(코드, 정답 수, 위반, 확인 필요, 놓침)

근거:
- **근거 일치율:** 최종 근거의 법 이름+조가 정답 legal_provisions와 하나라도 겹침. 정답 조문이 corpus에 없는 조각은 따로 뺀다.
- **검색 recall@3:** 모델과 무관. 도메인마다 한 번만 낸다.

문서 단위:
- 깨끗한 계약서 통과율
- 독소 계약서 경고율과 놓친 문서 목록
- K 곡선

검증 단계 통계:
- quote_mismatch 비율(toxic / safe 따로), 버린 근거 수, 근거 0개 비율, 파싱 실패율

시간:
- 조항당 평균·p90, 계약서 1장 평균 총시간, 모델 교체 시간

## 4. 모델 비교 통계
도메인별로, 같은 조항에 대한 두 모델의 결과를 짝지어 McNemar 검정(정확 검정)을 한다. p값과 두 모델이 갈린 조항 수(b, c)를 낸다.
- toxic 조각: 경고 포착 여부
- safe 조각: 오탐 여부
- 조합: 빠른 검토 = A.X 최적 조합, 정밀 검사 = EXAONE 최적 조합

## 5. 최적 조합 고르기 (dev 기준, 모델마다)
조건을 이 순서로 적용해 (AXOK, NUM2WAY, R, K)를 고른다.
1. 독소 계약서 놓침 0
2. 경고 포착률 최대
3. 깨끗한 계약서 통과율 최대
4. 오탐률 최소

세 도메인 합계 기준 하나, 도메인별 하나를 각각 낸다. 목표값(경고 포착 ≥90%, 오탐 ≤5%, 과잉 경고 ≤20%, 깨끗 통과 ≥80%) 통과 여부를 표시한다.

## 6. 깨끗한 계약서 실패 분석 (최적 조합 기준)
통과 못 한 깨끗한 계약서마다 막은 조항을 표로 낸다. 열: doc_id, 조항 앞 50자, std_item, 판정, 카드, review_source, 숫자 규칙 결과.
조항 유형별 집계도 낸다.

## 7. 섞어 쓰기(캐스케이드) 시뮬레이션 (LLM 호출 없음)
- 규칙: A.X가 위반·위험·확인 필요로 낸 조항만 EXAONE 판정을 쓰고, A.X가 "문제 없음"이면 그대로 둔다. 각 모델의 최적 조합 규칙을 적용한다.
- 지표: 3장 전부
- 시간: A.X 전체 + EXAONE이 다시 본 조항 + 모델 교체 시간 1회(1장 실측값)
- EXAONE 단독, A.X 단독과 나란히 놓는다.
