# 발표 전 최종 정리 (FINAL_POLISH)

순서대로 한다. **A장이 최우선이다.**

`CLAUDE.md` 규칙을 따른다.
- 고칠 파일은 `*_v숫자`로 먼저 백업한다(삭제 금지).
- 카드·판정 프롬프트·검증 규칙·검색 설정은 바꾸지 않는다.
- test 평가는 다시 돌리지 않는다.
- 숫자마다 명령과 출력 파일 경로를 붙인다. 확인 못 한 것은 "미확인"으로 쓴다.

## A. 큰 문제: 서비스에서 독소 계약서가 "안전"으로 나옴
`docs\tasks\SERVICE_PARITY.md`를 그대로 한다. 원인 찾기 → 고치기 → 3장 확인 순서다.
- 이미 시작했으면 이어서 한다.
- 원인이 정해지기 전에는 B~E장을 시작하지 않는다.

## B. 모델은 EXAONE 하나만 (분석과 채팅 모두)
- 서비스 모델은 `exaone`으로 고정한다.
  - 화면의 모델 선택 메뉴는 관리자 화면에서도 없앤다.
  - `/api/settings/model`은 exaone 이외의 값을 거절한다.
  - 서버가 A.X(8082)를 자동으로 띄우거나 전환하는 코드가 실행되지 않게 한다.
- **채팅도 EXAONE으로 답한다.** 지금 로컬 모드 채팅은 "안내 도우미(AI 답변 아님)"이다.
  - 맥락으로는 그 리뷰의 리포트(판정, 근거 조문 ID와 조문 문장, 수정 문구)와 가린 계약서 문장만 넣는다.
  - 사용자 질문도 가린 뒤 보낸다.
  - 답 끝에 "법률 자문이 아니에요. 중요한 결정 전에는 고용노동부 1350, 대한법률구조공단 132에 상담하세요."를 붙인다.
  - 출력은 400토큰 이내, temperature 0.2(지금 GPT 채팅 설정과 같게)로 한다.
  - 60초 안에 답이 없거나 EXAONE이 응답하지 않으면 지금의 안내 도우미 답으로 대신하고, "AI가 바빠서 기본 안내로 답했어요"를 표시한다.
  - 분석이 진행 중이면 입력창 위에 "분석 중에는 답변이 늦을 수 있어요"를 표시한다.
  - 채팅 라벨은 "AI 답변 · 법률 자문이 아니에요"로 바꾼다.
- 채팅 기록은 지금처럼 리뷰별로 저장한다.

## C. "내 검토 기록"을 왼쪽 사이드바 목록으로
지금은 상단 "내 검토 기록" 버튼을 누르면 브라우저 입력창(prompt)이 뜨고 id를 쳐야 한다. 이걸 없앤다.
- 왼쪽 사이드바의 "예시 샘플" 목록 **아래에 칸을 나눠서** "내 검토 기록" 영역을 만든다. 구분선과 제목을 단다.
  - 일상에서 쓰는 AI 채팅 서비스의 대화 기록처럼, 최신순 목록으로 보여 준다.
  - 항목마다 보여 줄 것: 제목(파일 이름, 없으면 "도메인 + 날짜"), 등급 배지(안전/주의/위험 색), 점수, 날짜·시각
  - 목록이 길면 이 영역 안에서만 스크롤한다.
  - 기록이 없으면 "아직 검토한 계약서가 없어요"를 표시한다.
- 항목을 누르면 **페이지 이동이나 입력창 없이** 바로 그 리뷰의 리포트, 채팅 기록, 원문을 워크스페이스에 연다(`/api/reviews`, `/api/reviews/{id}`).
  - 원본이 자동 삭제된 리뷰는 가린 텍스트로 보여 주고 "원본은 보안 정책에 따라 삭제됐어요"를 띄운다.
  - 지금 열려 있는 항목은 강조한다.
- 새 분석이 끝나면 목록 맨 위에 바로 추가된다(새로고침 불필요).
- 상단 "내 검토 기록" 버튼은 이 영역으로 스크롤하고 강조만 한다. prompt 창은 완전히 없앤다.
- 사이드바의 옛 문구 "원문은 메모리에서만 처리해요. 새로고침하면 내 파일 목록은 사라져요."는 지금 동작과 맞지 않는다. 다음 문구로 바꾼다: "업로드 원본은 암호화해 보관하고 24시간 뒤 자동 삭제돼요. 검토 기록은 로그인하면 다시 볼 수 있어요."

## D. 예시 화면에서 보인 문제
- **금전차용 예시**의 "원본 계약서" 이미지가 깨져서 보이지 않는다. 다른 예시와 같은 방식으로 페이지 이미지를 만들거나, 그게 안 되면 텍스트 보기로 띄운다.
- 예시 목록의 **"부동산 매매"**는 우리 서비스 도메인(근로·주택임대차·금전차용)이 아니다. 목록에서 숨긴다(파일은 지우지 않는다).

## E. 점수 계산 확인 (고치지 말고 보고만)
- 서비스에서 점수를 낼 때 "누락(필수 항목 not_present)"과 "불일치"가 실제로 몇 개로 세어져 감점되는지 확인한다.
- 리포트 하나를 예로 들어 계산식을 그대로 펼쳐 적는다. 예: `100 − (위반 1×20 + 위험 0 + min(확인 2×4, 20) + min(누락 1×5, 20) + min(불일치 0, 9)) = 67 → 위반 있음 → 최대 69 → 67, 주의`
- 결과는 `out\polish\score_explain.md`. 발표 자료에 쓴다.

## F. 확인 (브라우저 스크린샷, `out\polish\`)
1. 사이드바: 예시 샘플 아래 "내 검토 기록" 목록(기록 2개 이상)
2. 기록 항목 클릭 → 리포트와 채팅이 바로 열림(prompt 창 없음)
3. 금전차용 예시의 원본 이미지가 보임, "부동산 매매"가 없음
4. 모델 선택 메뉴 없음(일반 사용자, 관리자 둘 다)
5. 채팅 질문 "위험 조항 정리해줘" → EXAONE 답 + 고지문, 걸린 시간
6. A장 3장 비교표(SERVICE_PARITY 기준 통과 여부)
