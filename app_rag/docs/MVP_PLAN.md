# MVP 계획과 완료 기준

**MVP 한 줄:** 청년이 근로·임대·차용 계약서를 **PDF·HWP·HWPX·TXT 또는 붙여넣기**로 넣으면, 같은 검토 화면에서 **실제 RAG+A.X 결과**로 위험 조항, 근거 조문(corpus에 있는 것만), 수정 문구, 직접 확인할 것을 보여 준다. 샘플은 "예시 화면"으로 남긴다.

**진행 방법**
- 아래 단계를 순서대로 한다.
- 단계를 시작하기 전에 그 단계의 보고서가 `out\`에 이미 있는지 본다. 있으면 그 내용을 완료 기준과 대조한다. 기준을 넘었으면 다음 단계로, 아니면 이어서 고친다.
- 단계가 끝날 때마다 `docs\PROGRESS.md`에 적는다:
  - 단계 이름
  - 한 일
  - 완료 기준 표(기준 / 실제 / 근거 파일)
  - 남은 문제
- 사용자에게 묻지 않고 계속 진행한다. 단, CLAUDE.md의 "멈추고 물어야 하는 경우"에는 멈춘다.

---

## 1단계. 업로드 → 실제 분석 (지시: `tasks\CURSOR_PROMPT_MVP_UPLOAD.md`)
`out\mvp_upload\MVP_UPLOAD_REPORT.md`가 이미 있다. 먼저 이 보고서를 아래 기준으로 검토한다. 모자란 것만 고친다.

완료 기준:
- [ ] PDF(텍스트)·HWP·HWPX·TXT·붙여넣기 각각 끝까지 분석된다(스크린샷)
- [ ] 스캔 PDF는 안내가 뜨고 분석하지 않는다
- [ ] 사용자 결과 화면의 근거는 corpus ID만 보인다
  - 화면에 보이는 조문을 `corpus\emb_ids.json`과 대조한 표 첨부
- [ ] 원문 하이라이트를 찾은 비율 70% 이상(PDF 기준)
- [ ] `out\`·로그에 사용자 원문이 남지 않는다(검색 결과 첨부)
- [ ] 샘플 화면에 "예시 화면" 배지가 있고, "A.X 검색 근거" 문구가 없다

## 2단계. 근로 기준 카드 연결 (지시: `tasks\CURSOR_PROMPT_LAB_CARDS_CONNECT.md`)
- 카드는 `criteria\LAB_cards.yaml`, 원본 가이드는 `criteria\LAB_GUIDE.md`, 수정 기록은 `criteria\LAB_CARDS_FIX_LOG.md`
- B0 / B1 / B2를 비교한 뒤 가장 나은 설정을 기본으로 둔다. 어느 쪽을 골랐는지와 이유를 적는다.

완료 기준 (근로 dev):
- [ ] toxic 탐지율(위반·위험) 50% 이상
- [ ] safe 과잉 경고율(확인 필요) 20% 이하
- [ ] safe 오탐률(위반·위험) 5% 이하
- [ ] 깨끗한 계약서(toxic 0개 dev 문서)에서 위반·위험 0개, 확인 필요 3개 이하
- [ ] "확인 필요" 출처 표(A.X / needs_fact / 인용 불일치 / 근거 0 / 파싱 실패)

기준을 못 넘으면 고칠 곳의 우선순위:
1. verify 규칙
2. 카드 문구(safe·check_if를 더 구체적으로)
3. 판정 프롬프트 지시 줄

같은 단계는 3번까지만 시도한다. 카드 문구를 고칠 때 정답 데이터 문장을 보고 맞추지 않는다. 놓친 예시에서 **유형**만 보고 고친다.

## 3단계. 임대·차용 가이드와 카드
`tasks\CURSOR_PROMPT_LAB_GUIDE.md`와 `tasks\CURSOR_PROMPT_LAB_CARDS_FIX.md`의 방식 그대로 도메인만 바꿔 만든다.

**임대 (LEASE)**
- 바탕: 주택임대차표준계약서
  - `..\datasets\property\source_hwpx_originals\` 중 표준 양식 1장을 읽어 항목을 뽑는다
- 법: 주택임대차보호법·시행령, 민법(임대차 제618~654조, 제2조·제398조 등), `data_contract\law_api\현행` 원문
- 항목 예: 보증금·차임, 계약금·잔금, 임대차기간(2년 보장), 갱신요구권, 차임 증액(5%), 보증금 반환, 수선·유지, 원상복구(통상손모), 관리비, 전입·확정일자, 중도해지, 위약금, 출입, 특약

**차용 (LOAN)**
- 바탕: 표준 양식이 없다. 민법 제598조 이하와 이자제한법이 요구하는 항목으로 "표준형 차용증 항목표"를 먼저 만든다.
- 법: 민법(소비대차 제598~608조, 제379·387·388·397·398조), 이자제한법·최고이자율 규정, 보증인 보호를 위한 특별법, 민법 제428조의2·3
- 항목 예: 당사자, 원금, 이자율(연 20% 상한), 지연이자, 변제기, 변제 방법, 기한이익 상실, 보증(서면·최고액·기간), 담보, 특약

규칙은 근로와 같다.
- 기준마다 출처 `[법]` / `[표준]` / `[미확인]`
- 라벨 기준(toxic / check)과 일치시킨다
- `needs_facts`는 `uses_facts`와 `blocking_if`로 나눈다
- 카드 하나는 500자 이내
- 정답 문장 사용 금지
- 각 도메인 dev로 카드 전/후를 비교한다. 완료 기준은 2단계와 같다(도메인별).

## 4단계. 차용 화면과 마무리 기능
- [ ] 금전차용 샘플을 "예시 화면" 목록에 추가하고, 차용 계약서 업로드도 분석되게 한다
- [ ] 리포트 맨 위 3단계 문구
  - 위반·위험 0 + 확인 필요 ≤2 → "큰 문제는 보이지 않아요"
  - 위반·위험 0 + 확인 필요 ≥3 → "직접 확인할 부분이 있어요"
  - 위반·위험 ≥1 → "고쳐야 할 조항이 있어요"
- [ ] 필수 항목 누락(not_present) 표시: 근로는 근로기준법 제17조 항목 기준, 임대·차용은 3단계 항목표 기준
- [ ] "다음 행동": 상대에게 보낼 수정 요청 문구 묶음, 상담 창구(고용노동부 1350, 대한법률구조공단 132), "법률 자문이 아닙니다" 고지
- [ ] 사용자 결과 화면의 채팅 입력창에 "안내 도우미(AI 답변 아님)" 표시

## 5단계. 최종 평가 (test, 한 번만)
- 1~4단계 설정을 고정하고, 세 도메인 test 분할을 `--split test`로 **한 번** 돌린다.
- 지표: DEV_EVAL과 같은 표. 도메인별 + 합계, 비율 옆에 분자/분모.
- dev 결과와 나란히 놓은 표를 만든다.
- 결과가 나빠도 다시 튜닝해서 test를 또 돌리지 않는다. 결과를 그대로 적는다.
- 최종 보고서: `out\FINAL_REPORT.md`
  - 시스템 구성
  - 단계별 바뀐 것
  - dev/test 표
  - 한계: 합성 데이터, 노무사·변호사 검토 없음, 미수신 법령, 스캔 PDF 미지원 등
  - 발표용 데모 순서(샘플 → 내 파일 업로드)

## 끝
5단계 보고서를 쓰면 작업을 마친다. `PROGRESS.md` 맨 위에 세 가지를 적는다.
- 완료 기준 체크리스트 전체(통과/미통과/미확인)
- 사용자가 직접 해야 할 일(예: LAW_OC 설정, 발표 전 확인할 화면)
- 다음에 하면 좋은 것 3개
